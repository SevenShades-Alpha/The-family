# 家庭旅行日记小程序 · MVP 产品与技术设计

## 1. 产品目标与 MVP 边界

**目标：** 为同一个家庭提供私密的共同旅行档案，记录照片、文字、日期、城市、景点、酒店、餐厅、交通、花费、同行人及标签。

**第一版闭环：** 微信身份识别 → 创建或加入家庭 → 发布旅行日记 → 日记按旅行日期进入时间线 → 自动建立城市足迹 → 家人浏览、点赞、评论 → 查看家庭和个人统计。

**第一版暂缓：** 行政区 GeoJSON 边界填充、复杂角色体系、多家庭切换、二维码邀请、实时消息、日记编辑/删除、视频、离线编辑。地图先使用城市中心点和两种颜色的标记。

## 2. 页面结构

- `pages/login/index`：识别微信身份、同步头像昵称、创建家庭、输入邀请码加入。
- `pages/timeline/index`：时间倒序日记卡片；按城市/文字/标签关键字、成员、年份筛选。
- `pages/publish/index`：最多 9 张照片、正文、城市、省份、国家、地点、坐标、日期、酒店、景点、餐厅、交通、花费、同行人、标签。
- `pages/detail/index`：图片轮播、完整内容、旅行信息、地点地图、点赞和留言。
- `pages/map/index`：显示预设城市灰点/已访问橙点，支持城市搜索、手动打卡和城市详情。
- `pages/city/index`：首次/最近到访、到访估算次数及相关日记。
- `pages/mine/index`：家庭邀请码、成员头像昵称和加入时间、家庭总统计与个人统计。

## 3. 数据集合

所有集合由云函数访问，普通小程序客户端不直接读取或写入。

| 集合 | 核心字段 | 用途 |
|---|---|---|
| `users` | `openid`、`nickname`、`avatarUrl`、`familyId`、`createdAt`、`updatedAt` | 用户资料。`openid` 仅服务端使用，不下发到客户端 |
| `families` | `name`、`inviteCode`、`creatorId`、`memberCount`、`createdAt` | 家庭空间和邀请码 |
| `family_members` | `familyId`、`userId`、`openid`、`role`、`isActive`、`joinedAt` | 成员关系和成员状态 |
| `diaries` | `familyId`、`authorId`、`content`、`images`、`country`、`province`、`city`、`district`、`spot`、`hotel`、`restaurant`、`transport`、`amount`、`lat`、`lng`、`locationName`、`visitDate`、`travelers`、`tags`、`imageCount`、`createdAt`、`updatedAt` | 旅行日记主记录，图片只保存云存储文件 ID |
| `diary_images` | `familyId`、`diaryId`、`fileID`、`sort`、`caption`、`createdAt` | 图片扩展元数据；当前 MVP 可暂不单独写入 |
| `places` | `familyId`、`country`、`province`、`city`、`lat`、`lng`、`visitCount`、`firstVisit`、`lastVisit`、`diaryCount`、`createdAt`、`updatedAt` | 家庭级城市汇总，一家庭一城市的逻辑记录 |
| `checkins` | `familyId`、`userId`、`country`、`province`、`city`、`lat`、`lng`、`visitCount`、`firstVisit`、`lastVisit`、`source` | 成员级打卡记录 |
| `comments` | `familyId`、`diaryId`、`authorId`、`content`、`createdAt` | 日记评论 |
| `likes` | `familyId`、`diaryId`、`userId`、`createdAt` | 日记点赞关系，同一用户对同一日记应只有一条有效关系 |

建议后续为 `diaries` 建立 `familyId + visitDate` 查询索引；为 `places` 建立 `familyId + city` 查询索引；为 `checkins` 建立 `familyId + userId + city` 查询索引。MVP 中通过云函数先查询再更新，若数据规模变大，应使用事务/幂等标记来避免重复写入。

## 4. 云函数

### `api`

一个路由式业务云函数，减小 MVP 代码重复。可用 action：

- `auth.me` / `auth.login`：通过微信云上下文获取身份并创建/更新用户资料。
- `auth.createFamily` / `auth.joinFamily`：创建家庭或使用邀请码加入。
- `family.info` / `family.members`：家庭信息和成员列表。
- `diary.list` / `diary.publish` / `diary.detail`：读取列表、发布日记、读取详情。
- `diary.likeToggle` / `diary.comment`：点赞和留言。
- `stats.mapData` / `stats.checkin` / `stats.cityDetail` / `stats.summary`：地图数据、手动打卡、城市详情、统计。

进入家庭业务后，每次调用都从云端上下文取得 `OPENID`，在 `users` 和 `family_members` 中验证当前家庭成员资格，并确认被访问的日记/评论关系属于同一个 `familyId`。不信任客户端传入的 `openid` 或 `familyId`。

### `location`

腾讯位置服务代理云函数。`suggest` 请求地点关键词提示，`reverse` 将经纬度反解为省市区。需要在云函数环境变量配置 `TENCENT_MAP_KEY`；Key 不放在前端。

## 5. 家庭数据安全

1. 数据库集合禁止普通小程序客户端直接读写；云函数使用服务端 SDK，在验证成员身份后访问数据。
2. 不能只凭客户端传入的 `familyId` 授权。
3. 不能将 `openid`、地图服务 Key 或长期公开文件 URL 返回前端。
4. 图片由客户端上传到云存储，数据库仅记录文件 ID；云函数确认家庭权限后才生成短期 URL。
5. 邀请码是邀请机制，不替代身份识别和家庭成员校验。
6. 该模式不能防止已获准家庭成员截图、复制或主动泄露他们已看到的内容。

## 6. 地图点亮逻辑

1. 发布日记时必须填写城市；如果用户选取具体地点，则一并保存坐标。
2. 发布成功后，后端对 `places` 做家庭级 upsert，对 `checkins` 做作者级 upsert。
3. 地图加载 `places`，和本地预设城市列表按城市名归一化匹配；匹配成功的城市使用橙色标记，未匹配城市使用灰色标记。
4. 点击灰点可选择手动打卡，打卡后写入 `places` 和 `checkins`，地图重新加载后点亮。
5. 点击橙点进入城市详情，查询该家庭该城市的相关日记。
6. 第一版的城市到访次数是基于旅行日期的近似统计，不能当作精确的旅行次数。未知城市若没有坐标，无法放到地图上；后续可以扩充城市表或使用行政区划数据。

## 7. 部署清单

1. 使用自己的 AppID 在微信开发者工具打开项目。
2. 在 `miniprogram/app.js` 设置真实云环境 ID；`project.config.json` 使用当前项目的 AppID。
3. 开通云开发环境，创建九个数据库集合。
4. 把集合访问权限设为普通客户端不可读写、仅云函数/管理端访问。
5. 分别部署 `cloudfunctions/api` 和 `cloudfunctions/location`，选择云端安装依赖。
6. 若使用地点搜索，在 `location` 云函数环境变量设置 `TENCENT_MAP_KEY` 后重新部署。
7. 在小程序后台完成位置相关隐私保护指引配置，并按平台要求声明调用的定位接口。
8. 用两个微信账号分别验证创建家庭、邀请码加入、发布照片、自动点亮城市、点赞留言和成员隔离。

## 8. 迭代建议

- **可靠性：** 增加分页、编辑/删除日记、删除评论、重复提交防护和事务。
- **家庭管理：** 邀请二维码、成员移除、邀请码重置、操作审计。
- **旅行体验：** 行程归档、同行人从家庭成员多选、路线连线、城市按省份折叠、图片说明。
- **地图升级：** 增加世界城市、按国家/省份统计、GeoJSON 行政区边界填色和按年筛选足迹。
- **内容保全：** 数据导出、旅行年度回顾、生成家庭旅行相册或可打印纪念册。
